# 結合試験をやってみる

> 提出ブランチ：`feature/05-test-execution`（PRのbase：`develop`）

## この章のゴール

- 自分の環境へ導入した APK を使って結合試験を実施できる
- 実施結果をスプレッドシートとエビデンスで残せる
- テスト結果を PR で提出する流れまで通しで体験できる

## この章の位置づけ

この章は、課題1 の具体的な実施手順をそのまま進めるための章です。
[テスト案件の基本フロー](./03-test-workflow.md) では現場でよくある流れを整理しましたが、この章では「今、自分が何をやるか」に絞ります。
[再現できるバグ報告の書き方](./04-bug-report-basics.md) は、起票内容に迷ったときに見返してください。

## 事前準備

この章では、Drive 上の課題1資材と、自分の環境へ導入した APK を使います。
着手前に次をそろえてください。

- APK の導入と起動確認
- Android 実機
- 共有 Drive の `結合テスト > テストケース`
- 共有 Drive の `結合テスト > 課題1：設計書`
- 起票先の [TESTCURRICULUM プロジェクト](https://convi0310.backlog.com/projects/TESTCURRICULUM)
- 自分の Drive にコピーした `課題1_結合試験_<氏名>_YYYYMMDD` フォルダ内の `エビデンス`

ログインができない場合、ログイン後 TESTCURRICULUM のプロジェクトにたどり着けない場合は、この章を始める前に講師へすぐ連絡してください。
Android 実機がない場合も、この章を始める前に講師へすぐ連絡してください。

## この章で提出までにやること

1. 課題1 の配布フォルダを自分用にコピーする
2. 画面一覧、フロー図、画面設計書を見ながら観点を理解する
3. 実際に画面を操作して結果をシートへ記録する
4. 問題があれば Backlog へ起票し、シートへ戻す
5. シート URL と結果を PR（提出内容をレビューしてもらうためのページ）で提出する

## 手順

### 1. 自分用の作業フォルダを作る

配布された課題1用のシートは、そのまま編集しません。
共有 Drive の `結合テスト > テストケース` フォルダを、自分の Google Drive の `マイドライブ` 直下へ丸ごとコピーし、次の名前で保存してください。

- `課題1_結合試験_<氏名>_YYYYMMDD`

コピーしたフォルダの中に `IT1` と `IT2` がそろっていることを確認し、その 2 シートを自分用シートとして使います。
あわせて、同じフォルダの中に `エビデンス` フォルダを 1 つ作ってください。

`テストケース` フォルダまたは配下のシートが見当たらない場合は、この章を開始せず講師へすぐ連絡してください。

講師から別指示がない限り、課題1 では `IT1` を先に実施し、その後に `IT2` を実施します。

### 2. 参照資料を開く

少なくとも次を開いた状態で進めます。

- 課題1 の `IT1` と `IT2`
- `課題1：設計書`

### 3. Android 実機でテストを実施する

シートの項目を見ながら、少なくとも次を確認します。

- 正常系で基本フローが通るか
- 異常系で明らかに壊れないか
- 画面遷移やメッセージが設計書と大きくずれていないか

### 4. 結果とエビデンスを残す

- 実施したケースごとにシートへ結果を残す
- スクリーンショットは、自分の Drive にコピーした `課題1_結合試験_<氏名>_YYYYMMDD` フォルダの中に作成した `エビデンス` に、ケース ID と対応する名前で保存する
- バグがあれば Backlog へ起票し、シートへ起票番号を記載する
- 必要に応じて `templates/evidence-log-template.md` を個人メモとして使う

`エビデンス` は、テスト中に取得したアプリのスクリーンショットなどを残すためのものです。
この課題では、コピーした `課題1_結合試験_<氏名>_YYYYMMDD` フォルダの中に自分で作成した `エビデンス` に統一します。

### 5. Backlog 起票が必要ならシートへ戻す

不具合があった場合は、Backlog へ起票して終わりにしません。
保存後に発行された課題番号を、必ず `IT1` または `IT2` の `バグ票番号` 列へ戻します。
起票内容に迷った場合は [再現できるバグ報告の書き方](./04-bug-report-basics.md) を見返してください。
起票画面の入力方法は、[Backlog Wiki のチケット起票ページ](https://convi0310.backlog.com/wiki/TESTCURRICULUM/%E3%83%81%E3%82%B1%E3%83%83%E3%83%88%E8%B5%B7%E7%A5%A8) を参考にしてください。

### 6. 完了条件を確認する

課題1 は、次の状態になったら完了です。

- `IT1` と `IT2` の対象範囲を実施している
- `IT1` と `IT2` の自分用シート URL を提出できる状態になっている
- シートに判定が入っている
- 必要なエビデンスが保存されている
- 必要に応じて Backlog 番号がシートへ戻っている
- PR に提出情報をまとめている

PR には、少なくとも次をまとめてください。

- `IT1` の自分用シート URL
- `IT2` の自分用シート URL
- コピーした `課題1_結合試験_<氏名>_YYYYMMDD` フォルダ内の `エビデンス` の URL
- 必要に応じて Backlog 番号

## よくあるミス

- 結果だけ書いて、どの手順で確認したか残していない
- スクリーンショットの名前とケース ID が対応していない
- Backlog の起票先を確認しないまま実施を始めている
- `IT1` だけで終えて `IT2` を見落としている
- 問題が出たのに、起票番号をシートへ戻していない

## AIに聞いてみよう

```text
目的：結合試験の結果整理をしたい
現状：正常系は確認できたが、異常系の記録が曖昧
詰まりポイント：どこまで書けば他の人が追えるか不安
自分の仮説：手順、期待結果、実際結果をセットで書けば伝わる
確認したいこと：この記録で不足している観点を教えて
```
