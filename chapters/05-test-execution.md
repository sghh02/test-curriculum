# 結合試験をやってみる

> 提出ブランチ：`feature/05-test-execution`（PRのbase：`develop`）

## この章のゴール

- 自分の環境へ導入した APK を使って結合試験を実施できる
- 実施結果をスプレッドシートとエビデンスで残せる
- テスト結果を PR で提出する流れまで通しで体験できる

## 事前準備

この章では、Drive 上の課題1資材と、自分の環境へ導入した APK を使います。
着手前に次をそろえてください。

- APK の導入と起動確認
- Android 端末、または Android Studio のエミュレータ
- 共有 Drive の `結合テスト > テストケース`
- 共有 Drive の `結合テスト > 課題1：設計書`
- 起票先の Backlog プロジェクト
- My Drive 直下に作成した `課題1_エビデンス_<氏名>_YYYYMMDD`

## この章でやること

1. 課題1 の配布シートを自分用にコピーする
2. 画面一覧、フロー図、画面設計書を見ながら観点を理解する
3. 実際に画面を操作して結果をシートへ記録する
4. 問題があれば Backlog へ起票し、シートへ戻す
5. シート URL と結果を PR で提出する

## 進め方

### 1. 自分用のシートを作る

配布された課題1用のシートは、そのまま編集しません。
共有 Drive の `結合テスト > テストケース` にある `IT1` と `IT2` を、それぞれ自分の My Drive 直下へコピーし、次のような名前で保存してください。

- `課題1_結合試験_IT1_<氏名>_YYYYMMDD`
- `課題1_結合試験_IT2_<氏名>_YYYYMMDD`

`テストケース` 配下にシートが見当たらない場合は、この章を開始せず講師へ確認します。

講師から別指示がない限り、課題1 では `IT1` を先に実施し、その後に `IT2` を実施します。

### 2. 参照資料を開く

少なくとも次を開いた状態で進めます。

- 課題1 の実施シート
- `課題1：設計書`

### 3. テストを実施する

シートの項目を見ながら、少なくとも次を確認します。

- 正常系で基本フローが通るか
- 異常系で明らかに壊れないか
- 画面遷移やメッセージが設計書と大きくずれていないか

### 4. 結果を残す

- 実施したケースごとにシートへ結果を残す
- スクリーンショットは My Drive 直下の `課題1_エビデンス_<氏名>_YYYYMMDD` に、ケース ID と対応する名前で保存する
- バグがあれば Backlog へ起票し、シートへ起票番号を記載する
- 必要に応じて `templates/evidence-log-template.md` を個人メモとして使う

共有 Drive の `結合テスト > エビデンス` は講師用の見本または共有保管先です。
受講者は講師から指示がない限り、自分の `My Drive` にだけ保存して問題ありません。

### 5. 完了条件を確認する

課題1 は、次の状態になったら完了です。

- `IT1` と `IT2` の対象範囲を実施している
- `IT1` と `IT2` の自分用シート URL を提出できる状態になっている
- シートに判定が入っている
- 必要なエビデンスが保存されている
- 必要に応じて Backlog 番号がシートへ戻っている
- PR に提出情報をまとめている

## よくあるミス

- 結果だけ書いて、どの手順で確認したか残していない
- スクリーンショットの名前とケース ID が対応していない
- Backlog の起票先を確認しないまま実施を始めている
- `IT1` だけで終えて `IT2` を見落としている
- 問題が出たのに、起票番号をシートへ戻していない

## AIに聞いてみよう

```text
目的：結合試験の結果整理をしたい
現状：正常系は確認できたが、異常系の記録が曖昧
詰まりポイント：どこまで書けば他の人が追えるか不安
自分の仮説：手順、期待結果、実際結果をセットで書けば伝わる
確認したいこと：この記録で不足している観点を教えて
```
