# テスト案件の進め方

## この章のゴール

- テスト案件の基本的な流れを説明できる
- 実施前に何を準備するか整理できる
- 後半の課題で迷わないように、作業の順番を把握する

## 現場でよくある流れ

テスト案件では、次の流れで動くことが多くあります。

1. 仕様や資料を読む
2. 実施対象と観点を確認する
3. テストを実施する
4. エビデンスと結果を残す
5. 問題があれば報告する
6. 必要なら再確認する

## このカリキュラムでの進め方

### 結合試験の課題

- 講師から配布された APK を使ってテストを実施する
- `templates/evidence-log-template.md` と `templates/bug-report-template.md` をコピーして記録する
- 結果を PR で提出する

### 単体試験の設計課題

- `samples/test-design/` の見本資料を読む
- `templates/test-case-template.md` をコピーして設計する
- 観点と条件を PR で提出する

## 準備で見るべきもの

- 対象の概要
- 確認対象の画面や機能
- 期待結果の基準
- 記録の残し方

## よくあるミス

- 作業を始めてから必要資料を探す
- エビデンスの保存ルールを決めずに進める
- 問題が出たあとに報告テンプレートを開く
