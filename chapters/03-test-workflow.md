# テスト案件の進め方

## この章のゴール

- テスト案件の基本的な流れを説明できる
- 実施前に何を準備するか整理できる
- 後半の課題で迷わないように、作業の順番を把握する

## 現場でよくある流れ

テスト案件では、次の流れで動くことが多くあります。

1. 仕様や資料を読む
2. 実施対象と観点を確認する
3. テストを実施する
4. エビデンスと結果を残す
5. 問題があれば報告する
6. 必要なら再確認する

## このカリキュラムでの進め方

### 結合試験の課題

- 自分の環境へ APK を導入してテストを実施する
- Drive 上の課題1用スプレッドシートを自分用にコピーして記録する
- 必要に応じて Backlog に起票し、結果を PR で提出する

### 単体試験の設計課題

- Drive 上の課題2用設計書を読み、`テストケース` 配下の試験紙を自分用にコピーして設計する
- `templates/submission-note-template.md` を補助的に使って設計意図を整理する
- 観点と条件を PR で提出する

## 準備で見るべきもの

- 対象の概要
- 確認対象の画面や機能
- 期待結果の基準
- 記録の残し方
- 自分用コピーのシート名と保存先
- エビデンスとバグ報告の戻し先

## よくあるミス

- 作業を始めてから必要資料を探す
- 配布シートを直接編集する
- エビデンスの保存ルールを決めずに進める
- 問題が出たあとに報告テンプレートを開く
