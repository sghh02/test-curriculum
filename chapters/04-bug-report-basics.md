# 再現できるバグ報告の書き方

## この章のゴール

- バグ報告に最低限必要な要素を説明できる
- 感想ではなく事実で書く意識を持てる
- 次章の結合試験課題で、報告テンプレートを迷わず使える

## バグ報告に必要な5要素

1. 何をしたか
2. 何が起きたか
3. 本来どうあるべきか
4. 再現手順
5. 環境情報

## 伝わる書き方

- 「変だった」ではなく、何がどう違ったかを書く
- 画面名、操作、入力値を省略しない
- 期待結果と実際結果を並べて書く

## このカリキュラムで使うテンプレート

後半の課題では、主に次の2つを使います。

- 下書き用: `templates/bug-report-template.md`
- 実運用: バグ起票フォーム
  - <https://docs.google.com/forms/d/1-vPNHLyxtHKpMS88E2QgLLWF19sY3Ex_4CSjlQ0wqnQ/edit?usp=drivesdk>

まずは見出しの意味だけ理解し、実際に起票したらシート側へ起票番号を戻す流れを押さえてください。

```text
事象:
再現手順:
期待結果:
実際結果:
補足:
```

## よくあるミス

- 感想や推測だけを書いて、事実が抜ける
- 再現手順が「同じことをしたら起きる」になっている
- 期待結果が書かれていない
- 起票しただけで満足し、実施シートへ番号を書き戻していない

## AIに聞いてみよう

```text
目的：バグ報告を短く分かりやすくしたい
現状：事象と手順は書けるが、期待結果が曖昧になりがち
詰まりポイント：どこまで書けば再現しやすいか分からない
自分の仮説：画面名、入力値、押したボタンを明記するとよさそう
確認したいこと：この報告文で足りない情報を教えて
```
