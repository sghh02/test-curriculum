# 第6章: 再現できるバグ報告の書き方

## この章のゴール

- バグ報告に最低限必要な要素を説明できる
- 感想ではなく事実で書く意識を持てる
- 次章の結合試験課題で、起票に必要な項目を迷わず整理できる

## バグ報告に必要な5要素

1. 何をしたか
2. 何が起きたか
3. 本来どうあるべきか
4. 再現手順
5. 環境情報

## 伝わる書き方

- 「変だった」ではなく、何がどう違ったかを書く
- 画面名、操作、入力値を省略しない
- 期待結果と実際の結果を並べて書く

## このプログラムで使うテンプレート

後半の課題では、主に次の2つを使います。

- 下書き用: `templates/bug-report-template.md`
- 実運用: GitHub の Issue

テンプレートは任意の下書き用です。まずは見出しの意味だけ理解し、実際に起票したらシート側へ Issue 番号を戻す流れを押さえてください。
このプログラムで使う起票先は [test-qa リポジトリ](https://github.com/sghh02/test-qa/issues) です。
GitHub アカウントでログインしていれば、招待なしでそのまま起票できます。
ログインできない場合、`New issue` を押しても起票画面にたどり着けない場合は、その時点で講師へすぐ連絡してください。

## GitHub での起票手順

1. [test-qa リポジトリ](https://github.com/sghh02/test-qa/issues) の `Issues` タブを開く
2. 緑色の `New issue` ボタンを押す
3. `バグ報告` を選ぶ
4. 件名（タイトル）とフォームの項目を埋める
5. `Create` を押す
6. 発行された Issue 番号をスプレッドシートへ戻す

Issue 番号は、たとえば `#12` のような形で表示されます。
番号だけでは分かりにくいときは、Issue の URL をそのまま貼っても構いません。

起票フォームには、この章で学んだ 5 要素がそのまま項目として並んでいます。
`*` が付いた項目は、空欄のままでは登録できません。埋めながら、何を書くべきかを確認してください。

## 見本と同じように書く

書き方の見本を [見本の Issue](https://github.com/sghh02/test-qa/issues/1) に置いてあります。
Issue 一覧の先頭に固定してあるので、迷ったらこれを開いてください。

**この見本と同じように書けば、必要な情報はそろいます。**
とくに次の 3 点は、見本の書き方をそのまま真似してください。

- 再現手順は、どの画面で何を押し、何を入力したかを 1 手ずつ番号で書く
- 期待結果は、設計書のどこを根拠にしたかまで書く
- 実際の結果は、期待結果と並べて読んだときに差が分かるように書く

## 起票のルール

このプログラムでは、次のルールで揃えます。

| 項目 | ルール |
| --- | --- |
| 件名 | `[結合テスト][ケースID][画面名] 事象` の形にそろえる |
| テスト種別 | フォームの `テスト種別` で結合／単体を選ぶ |
| 優先度 | 進行不能なら高め、回避できるなら中以下を目安にする |
| 担当者 | 講師の指示がなければ空欄でよい |
| ラベル | 自分では付けない。講師がトリアージで付ける |

件名は、フォームを開いた時点で `[結合テスト][ケースID][画面名] 事象を一行で` が入っています。
`ケースID` `画面名` `事象を一行で` の 3 か所を、必ず自分の内容に置き換えてください。

> **トリアージとは**
>
> 起票された不具合を確認して、優先度や対応の要否を仕分けることです。
> 現場でも、起票するのはテスター、ラベルを整えるのは開発側や QA リード、と役割が分かれていることが多くあります。

下書き用のテンプレートは次の通りです。フォームへ入力する前に、手元で整理したいときに使ってください。

```text
事象:
再現手順:
期待結果:
実際の結果:
補足:
```

起票後にやることも忘れないでください。

- 発行された Issue 番号を確認する
- 実施シートの `備考` 列へその番号を記載する
- 必要ならエビデンス名も一緒に残して、あとで照合できるようにする

## よくあるミス

- 感想や推測だけを書いて、事実が抜ける
- 再現手順が「同じことをしたら起きる」になっている
- 期待結果が書かれていない
- 件名にケース ID や画面名がなく、あとで追えない
- 起票しただけで満足し、実施シートへ番号を書き戻していない

## AIに聞いてみよう

```text
目的：バグ報告を短く分かりやすくしたい
現状：事象と手順は書けるが、期待結果が曖昧になりがち
詰まりポイント：どこまで書けば再現しやすいか分からない
自分の仮説：画面名、入力値、押したボタンを明記するとよさそう
確認したいこと：この報告文で足りない情報を教えて
```
